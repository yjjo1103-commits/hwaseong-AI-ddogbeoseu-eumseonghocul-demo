---
name: 브라우저 음성 API 테스트
description: Web Speech API와 TTS를 자동화할 때 지연·중복·역순 이벤트를 안전하게 다루는 원칙
---

음성 통화 상태는 브라우저 이벤트 순서만 신뢰하지 말고, 활성 통화 세션과 연결된 이벤트인지 확인한 뒤 변경해야 한다. 통화 종료 또는 재시작 시 예약된 콜백과 이전 인식 인스턴스를 함께 무효화한다.

**Why:** 브라우저 자동화용 음성 API 스텁은 실제 환경과 달리 시작·결과 이벤트가 역순으로 오거나 TTS 완료 콜백을 중복 호출할 수 있다. 이를 그대로 처리하면 종료 후 마이크가 다시 켜지거나 완료 화면이 듣기 상태로 덮어써진다.

**How to apply:** 음성 인식·합성 흐름을 수정할 때 세션 토큰, 타이머 정리, 인식 인스턴스 소유권, 완료 콜백의 단일 실행을 유지한다. 테스트 실패 시 실제 앱 오류와 스텁 이벤트 모델 문제를 분리해 확인한다.
